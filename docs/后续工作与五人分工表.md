# 后续工作分解与五人分工表
## —— 零食标签数据与查询系统（V2.2）

> 用途：配合演讲稿使用。上台时可作为投影页，或打印发给老师。
> 一句话主线：**前端已交付的是"窗口 + 数据契约"；接下来把它变成"真实数据库 + 采集解析后端 + 打通的前后端"。**

---

## 一、后续七阶段工作分解

| 阶段 | 工作 | 具体内容 | 对应页面 | 数据库课考点 | 交付物 |
|---|---|---|---|---|---|
| 1 | 数据库设计 | ER 图、约 20 张表落 SQL、3NF、主外键约束、索引、视图 | 仪表盘 / 全局 | 建模、范式、完整性约束 | 建表脚本、ER 图 |
| 2 | 采集器开发 | OFF API 分页抓取、限速 4 秒、503 退避、断点续跑、原始 JSON 入库 | 数据源与采集 | 数据入库管理、原始层留存 | 采集脚本、raw_record 数据 |
| 3 | 清洗整合 | 条码去重、多源合并、字段规范化、冲突处理、缺失标记 | 产品检索与对比 | ETL、多源合并、质量标记 | 标准层 product 数据 |
| 4 | 配料解析 | 文本拆分、括号嵌套、INS/别名映射、添加剂识别、待确认队列 | 配料标准化 | 文本转结构化关系表 | product_ingredient + 词典 |
| 5 | 规则与解读 | 添加剂知识库、user_rule 关注规则、三级解读输出、版本化 | 知识与关注规则 / 成分解读 | 表驱动、版本化、结果留痕 | 知识表、规则表、解读结果 |
| 6 | 前后端对接 | API 替换 mock、统计做成视图、导出、前台筛选接真实数据 | 统计与报告 / 访客筛选页 | 视图、聚合查询 | 可用系统、统计报告 |
| 7 | 测试与工程化 | 建索引、EXPLAIN 对比、事务回滚、备份恢复、文档 | 全局 | 性能优化、事务、备份 | 测试报告、性能对比、文档集 |

## 二、五人分工矩阵

| 成员 | 角色定位 | 负责阶段 | 负责模块（FR） | 对应页面 | 主要表 / 产出 |
|---|---|---|---|---|---|
| **A（组长）** | 数据库设计 & 总协调 | 1、7 | FR-7、全局设计 | 仪表盘、统计与报告 | ER 图、DDL、索引视图、EXPLAIN、备份脚本 |
| **B** | 采集工程师 | 2 | FR-1 | 数据源与采集 | crawl_task、raw_record、采集脚本 |
| **C** | 数据解析工程师 | 3、4 | FR-2、FR-3 | 产品检索、配料标准化 | product、label_info、product_ingredient、词典 |
| **D** | 规则与解读工程师 | 5 | FR-4、FR-5 | 知识与关注规则、成分解读 | additive、user_rule、interpret_run/result |
| **E** | 应用与测试工程师 | 6、测试 | FR-6、FR-8、FR-9 | 访客筛选页、系统管理 | api 层、前台对接、sys_user/log、测试与文档 |

**分工逻辑（汇报时讲这句）**：
> 按数据流切，不按页面切。B 把数据抓进来 → C 把数据理干净 → D 让数据能回答问题 → E 把结果送到用户面前 → A 负责底下整座数据库的地基。每个人的产出是下一个人的输入，且每人都有数据库课程能打分的交付物。

## 三、时间线（六周）

| 周次 | 任务 | 里程碑 |
|---|---|---|
| 第 1~2 周 | 阶段 1 + 2 | 数据库建好，入库 300~500 条真实数据 |
| 第 3 周 | 阶段 3 + 4 | 数据完成标准化，配料解析出结构化表 |
| 第 4 周 | 阶段 5 | 知识库 + 规则表 + 解读引擎跑通 |
| 第 5 周 | 阶段 6 + 7 | 前后端打通，索引/事务/性能验证完成 |
| 第 6 周 | 测试 + 文档 + 演示准备 | 完整可演示系统 + 全套课程材料 |

| A4 | 解读、查询、对比产出结果且可追溯 | D |

## 五、给老师的一句话

> 我们这个阶段交付的是前端框架和完整的数据契约；后续按"建库 → 采集 → 清洗 → 解析 → 规则解读 → 前后端打通 → 性能与文档"七步推进，五个人按数据流分工，把页面背后的演示数据换成真实的关系数据库，做成可用系统。
